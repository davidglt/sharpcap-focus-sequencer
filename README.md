# SharpCap Focus Sequencer

`sharpcap-focus-sequencer` applies on-demand thermal focus compensation to ZWO
EAF focusers through ASCOM. It reads the thermal model produced by the sibling
`sharpcap-focus-temperature` project, refreshes that model from SharpCap logs
before a normal run, reads the EAF temperature, and moves the focuser to the
compensated position.

It supports two independent optical trains:

| Tube | Equipment | Filter offsets | Daily log |
|---|---|---:|---|
| `main` | Celestron C8 with f/6.3 reducer, ASI2600MC Pro, and ZWO EAF | Yes | `logs\YYYYMMDD_focus_sequencer.log` |
| `guide` | Sky-Watcher 50ED, ASI224MC, and second ZWO EAF | No; always zero | `logs\YYYYMMDD_focus_sequencer_guide.log` |

## How it works

For each run, the sequencer:

1. Selects the optical train with `--tube main` or `--tube guide`.
2. Loads the corresponding focus-state JSON generated by
   `sharpcap-focus-temperature`.
3. Connects to the selected ASCOM focuser and safely exits if the focuser is
   already moving. A per-focuser lock prevents overlapping sequencer runs.
4. Refreshes the state JSON from recent SharpCap logs, except when `--dry-run`
   is used. If the refresh fails, the cycle is aborted; the previously loaded
   state is not used for a movement. The refresh has a configurable timeout.
5. Calculates the thermal target:

   ```text
   base_target = focus_ref + TCF × (current_temperature - reference_temperature)
   final_target = base_target + filter_offset
   ```

6. Applies backlash compensation when the target is below the current position.
7. Writes `START`, refresh status, correction details, and `END` to the daily
   log for the selected tube.

## Requirements

- Windows with ASCOM Platform and a ZWO EAF accessible through ASCOM.
- Python 3.10 or later is recommended.
- A sibling clone of `sharpcap-focus-temperature` alongside this repository:

  ```text
  C:\astro\sharpcap-focus-sequencer
  C:\astro\sharpcap-focus-temperature
  ```

- A valid thermal-state file for each tube:

  ```text
  C:\astro\sharpcap-focus-temperature\sharpcap_focus_state.json
  C:\astro\sharpcap-focus-temperature\sharpcap_focus_state_guide.json
  ```

- Separate virtual environments are supported. The sequencer prefers to run
  the producer with:

  ```text
  C:\astro\sharpcap-focus-temperature\.venv\Scripts\python.exe
  ```

  That environment must include the producer dependencies, including `numpy`
  and `matplotlib` when needed by `sharpcap_focuser.py`.

## Installation

Clone both projects as sibling repositories under a common parent directory.
Create independent virtual environments and install each project's
requirements into its own environment.

```cmd
cd C:\astro\sharpcap-focus-sequencer
py -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt

cd C:\astro\sharpcap-focus-temperature
py -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Copy `focus_sequencer.properties.example` to `focus_sequencer.properties` and
configure the main-tube filter offsets. Position 1 must be the no-filter
reference filter, with an offset of zero.

## Launchers

Use the supplied BAT files from SharpCap external-command steps or a command
prompt.

| Launcher | Python command | Tube |
|---|---|---|
| `run_focus.bat` | `focus_sequencer.py --tube main` | Main imaging train |
| `run_focus_guide.bat` | `focus_sequencer.py --tube guide --ascom-id ASCOM.EAF_2.Focuser --state-json ..\sharpcap-focus-temperature\sharpcap_focus_state_guide.json` | Guide train |

Both launchers forward additional arguments using `%*`. For example, to test
without moving the focuser:

```cmd
run_focus.bat --dry-run
run_focus_guide.bat --dry-run
```

The guide launcher explicitly selects `sharpcap_focus_state_guide.json` and
`ASCOM.EAF_2.Focuser`. The main launcher uses `sharpcap_focus_state.json` and
`ASCOM.DeviceHub.Focuser` by default. These ASCOM ProgIDs can be overridden
with `--ascom-id`.

## Command-line usage

### Main tube

```cmd
.venv\Scripts\python.exe focus_sequencer.py --tube main
.venv\Scripts\python.exe focus_sequencer.py --tube main --filter 2
.venv\Scripts\python.exe focus_sequencer.py --tube main --filter 2 --dry-run
.venv\Scripts\python.exe focus_sequencer.py --tube main --config custom.properties
.venv\Scripts\python.exe focus_sequencer.py --tube main --refresh-timeout 600
```

### Guide tube

```cmd
.venv\Scripts\python.exe focus_sequencer.py --tube guide
.venv\Scripts\python.exe focus_sequencer.py --tube guide --dry-run
.venv\Scripts\python.exe focus_sequencer.py --tube guide --state-json "C:\astro\sharpcap-focus-temperature\sharpcap_focus_state_guide.json"
```

The guide tube always uses a zero filter offset. `--filter` and `--config`
are supported only with `--tube main` and are rejected for `--tube guide`.
The default ASCOM ProgID is `ASCOM.DeviceHub.Focuser` for the main tube and
`ASCOM.EAF_2.Focuser` for the guide tube.

## Logs

The daily log filename depends on the selected tube:

```text
--tube main   -> logs\YYYYMMDD_focus_sequencer.log
--tube guide  -> logs\YYYYMMDD_focus_sequencer_guide.log
```

Each correction cycle records the model reference, temperature, temperature
delta, thermal coefficient, filter context, calculated target, starting
position, requested correction, backlash usage, final position, and exit
reason.

Example:

```text
2026-09-27 03:18:24 | START | tube=main | ref=... | focus_ref=... | T_ref=... | TCF=...
2026-09-27 03:18:29 | INFO  | tube=main | T=... | dT=... | target=... | pos=... | correction=... | backlash=False | final=...
2026-09-27 03:18:29 | INFO  | END   | pos=... | reason=ok
```

Possible exit reasons include:

```text
ok
ok_with_warning
min_correction
busy
dry_run
error
configuration_error
state_refresh_failed
move_timeout
```

## Main-tube filters

The main-train thermal model is calibrated at filter-wheel position 1,
`No filter`. The sequencer first calculates the thermal target without a
filter, then applies the selected filter offset:

```text
base_focus_target = focus_ref + TCF × (T_current - T_ref)
final_focus_target = base_focus_target + filter_offset_steps
```

Keep this setting:

```properties
filter.1.offset_steps=0
```

Configure the capture filters and their offsets in
`focus_sequencer.properties`.

## Safety behavior

- If the focuser reports `IsMoving=True`, the sequencer skips the cycle to
  avoid competing with SharpCap autofocus.
- A correction that requires backlash overshoot is skipped when its absolute
  size is below `--min-correction`.
- Corrections that do not require backlash are applied even when small to
  avoid accumulating thermal drift.
- The target is clamped to the ASCOM focuser limits when the driver provides
  them.
- `--dry-run` reads state, position, and temperature, but does not refresh the
  state JSON or move the focuser.
- A failed state refresh aborts a normal cycle. The sequencer never falls back
  to a previously loaded state for a focuser movement.
- State JSON numeric values are validated before use; focus positions must be
  non-negative integers and model values must be finite.
- The calculated target is checked for finite arithmetic and constrained to
  the ASCOM focuser position range before a movement is requested.
- If a movement exceeds `--move-timeout`, the sequencer sends the ASCOM `Halt`
  command. Logs report whether the command was sent or failed, whether the
  focuser still reports movement, and its last readable position; the state is
  not updated after a timed-out movement.
- Runtime state updates use a temporary file and atomic replacement so an
  interrupted write does not leave a partially written JSON file.
- Only one sequencer process can operate a given ASCOM ProgID at a time. The
  focuser's `IsMoving` state is checked again immediately before each movement
  to reduce collisions with SharpCap autofocus.
- `--refresh-timeout SECONDS` limits how long the producer may take to refresh
  the model (default: 300 seconds). The cycle aborts if the timeout is reached.

## Troubleshooting

### `ModuleNotFoundError` for `numpy` or `matplotlib`

`sharpcap_focuser.py` belongs to `sharpcap-focus-temperature` and must run with
that project's virtual environment. Verify the interpreter and dependencies:

```cmd
C:\astro\sharpcap-focus-temperature\.venv\Scripts\python.exe -c "import sys, numpy, matplotlib; print(sys.executable); print('OK:', numpy.__version__, matplotlib.__version__)"
```

If the environment is missing or incomplete, recreate it in the producer
repository:

```cmd
cd C:\astro\sharpcap-focus-temperature
py -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### `UPDATE FAILED`

This means the producer did not successfully refresh the thermal state. Check
the `UPDATE FAILED` entry in the daily log for the selected tube. The
sequencer aborts the correction cycle rather than moving the focuser with a
previously loaded state. Fix the producer/configuration issue and retry.

### Guide focuser connection

The guide launcher uses `ASCOM.EAF_2.Focuser` by default. ASCOM ProgID
assignment can change with USB enumeration order. Run `detect_focusers.py` to
verify which ProgID maps to each EAF, then adjust the launcher or supply an
explicit `--ascom-id` if the mapping changes.

### Cannot write `sharpcap_final_focus.csv`

Do not configure the producer to write generated files under:

```text
C:\Program Files\SharpCap 4.1 (64 bit)
```

Use a writable data directory, such as `C:\astro` or the producer project
directory.

### Verify both logs

After running both launchers with `--dry-run`, confirm that both log files
exist:

```cmd
dir logs\*_focus_sequencer.log
dir logs\*_focus_sequencer_guide.log
```

The main log should contain `tube=main`; the guide log should contain
`tube=guide`.

## Integration with SharpCap Sequence Analyzer

Separate logs allow `sharpcap-sequence-analyzer` to correlate thermal
corrections accurately:

| SharpCap command | Focus Sequencer log |
|---|---|
| Main-tube focus command | `*_focus_sequencer.log` |
| Guide-tube focus command | `*_focus_sequencer_guide.log` |

The analyzer can report temperature, TCF, requested correction, backlash,
positions before and after, and exit reason separately for the C8 and 50ED.
